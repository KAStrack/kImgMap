Documentation

Installation

Include the CSS and JS on your page. Both files are standalone — no build step or dependencies required. Download them from the GitHub repository (kImgMap.js / kImgMap.css in the root, minified builds in docs/):

html 
<link rel="stylesheet" href="kImgMap.css">
<script src="kImgMap.js"></script>

Or load the minified builds from the jsDelivr CDN (pin a release tag such as @v1.15.0 for production):

html 
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/KAStrack/kImgMap/docs/kImgMap.min.css">
<script src="https://cdn.jsdelivr.net/gh/KAStrack/kImgMap/docs/kImgMap.min.js"></script>

Or use it as a module. docs/kImgMap.mjs (and docs/kImgMap.min.mjs) is an ES module build with a default and a named export; kImgMap.js is UMD, for <script> tags, CommonJS and AMD. Installed as a package (e.g. npm install github:KAStrack/kImgMap), import picks the ES module and require the UMD build automatically:

js 
// Bundlers (Vite, webpack, Rollup, esbuild) and Node
import kImgMap from 'kimgmap';
import 'kimgmap/kImgMap.css';

// Native browser modules — a local copy or the CDN
import kImgMap from 'https://cdn.jsdelivr.net/gh/KAStrack/kImgMap@v1.15.0/docs/kImgMap.min.mjs';

// CommonJS
const kImgMap = require('kimgmap');
AMD: if the page has an AMD loader such as RequireJS, the UMD build registers itself as an anonymous AMD module instead of setting window.kImgMap — load it through the loader (require(['kImgMap'], …)), or use the ES module build.

Load it one way per page: an app that both imports and requires it gets two separate copies, which don't know about each other's editors (one-editor-per-image and the modal's page locking are per copy).

Browser support

Current Chrome, Edge, Firefox and Safari (desktop and mobile) — the test suite runs in Chromium, Firefox and WebKit. The code uses ES2020 and Pointer Events, so the practical minimum is Chrome/Edge 90, Firefox 90 and Safari 14.1 (iOS 14.5). Browsers without the inert attribute (before Chrome 102, Firefox 112, Safari 15.5) still trap Tab inside the modal, but a screen reader's virtual cursor can reach the page behind it.

Quick Start

Point new kImgMap() at an <img> element and pass the associated textarea via the textarea option. The textarea can be anywhere in the document — it does not need to share a container with the image.

html 
<img id="my-image" src="photo.jpg" alt="Map image">
<textarea id="my-map"></textarea>
js 
const editor = new kImgMap(
  document.getElementById('my-image'),
  {
    textarea: document.getElementById('my-map'),
    mode:     'modal',
  }
);

kImgMap will hide the textarea and render an "Edit Image Map" button in its place. Clicking the button opens the modal editor.

Auto-init

Add data-kimgmap to a container element and call kImgMap.init() — it will find the <img> and optional <textarea> inside automatically.

html 
<div data-kimgmap
     data-kimgmap-mode="modal"
     data-kimgmap-shape="rect"
     data-kimgmap-output="areas">
  <img src="photo.jpg" alt="">
  <textarea></textarea>
</div>

<script>
  kImgMap.init(); // initialises all [data-kimgmap] containers
</script>

Pass an options object as the second argument to new kImgMap() or kImgMap.init().

shapes ['rect','circle','poly'] Enabled drawing tools. Pass a subset to restrict which shapes are available.

customAttributes [] Additional attributes to expose in the Properties panel. Each entry is either a plain string or { attr, label }. E.g. [{ attr: 'data-value', label: 'Value' }, 'data-category']. Non-empty values are written to the output HTML (subject to outputAttributes, if set).

  if (attr === 'data-value')

}
Returned values are immediately applied to the area and reflected live in any visible Properties panel inputs.
outputAttributes null Controls which attributes are written to the <area> HTML output, and in what order. When null (default), every attribute stored on the area is written — standard, custom, and any parsed from existing HTML. confirmDiscard true When closing the modal with unsaved changes via Escape, the × button or a backdrop click, ask “Discard your unsaved changes?” first. The Cancel button always discards without asking. Labels customisable via labels.discardPrompt, labels.keepEditing and labels.discardChanges.
mandatoryTitles false When true, the Save button will refuse to close if any area is missing a title. Areas without a title are highlighted with a pulsing red error cue and an error banner is shown above the canvas. The cue clears automatically as each title is filled in. The title can come from a title field or be mirrored from another attribute via onAttributeChange. Applies to modal mode (inline mode has no Save step). showTextarea false Controls textarea visibility alongside the trigger button (modal mode only).
false — textarea is hidden entirely (default).
true — textarea is always visible below the trigger button.
'optional' — textarea is hidden initially; a Show Code toggle button appears to the right of the trigger button to show or hide it.
showAttributePanel true Whether to show the Properties panel in the sidebar when an area is selected.
editable true When false, areas cannot be moved or resized after drawing (draw-only mode).
theme null Colour theme of the inline editor or the modal: 'light', 'dark', or 'auto' (follows the operating system's setting, live). null leaves it to your CSS. See Dark Theme.
className '' Extra class name(s) for the editor (inline) or the modal overlay — e.g. to scope a custom theme to one instance, modal included. See Full Custom Theme Example.
textarea auto-detect The textarea to read from and write to. Accepts a CSS selector string or a DOM element. The textarea can be anywhere in the document. If omitted, kImgMap looks for a sibling <textarea> in the same parent element as the image.
labels see below Object of UI string overrides. Useful for localisation.
onUpdate null Callback fired on every change: (htmlString, areasArray) => {}. Callbacks receive copies of the areas — changing them doesn't change the editor (use setAreas()).
onSave null Callback fired when the modal Save button is clicked: (htmlString, areasArray) => {}.
onOpen null Callback fired when the modal opens.
onClose null Callback fired when the modal closes: (wasSaved) => {}.

Modes

Modal (mode: 'modal')

The default. kImgMap hides the textarea and inserts an "Edit Image Map" button next to it. Clicking the button opens a full-screen modal with the editor. Changes sync to the textarea live while you edit; on Save the onSave callback fires. Cancel restores the textarea and areas to their state when the modal opened; Escape, × and a backdrop click do the same, but ask first if there are unsaved changes (see confirmDiscard).

Round trips are lossless: attributes are written back exactly as parsed (including empty ones like alt=""), <area> tags that can't be edited visually (shape="default", too few coords) are kept verbatim and appended, and the textarea's <map name> is reused when mapName isn't set.

Inline (mode: 'inline')

The editor is embedded directly on the page. The original image is moved into the editor container. Changes are written to the textarea — and onUpdate fires — on every action, without any Save button. Call editor.destroy() to remove the editor and restore the original image.

Shapes

Rectangle ('rect')

Click and drag to draw. Eight resize handles appear on corners and edge midpoints. Coordinates are stored as x1,y1,x2,y2.

Circle ('circle')

Click to set the center, drag to set the radius. One resize handle appears on the east edge. Coordinates: cx,cy,r.

Polygon ('poly')

Click to add vertices one at a time. Close the shape by either:

  • Double-clicking (or double-tapping) to place the final vertex
  • Clicking or tapping the last vertex again
  • Clicking or tapping on (or very near) the first vertex

Press Escape to cancel an in-progress polygon. Coordinates: flat x1,y1,x2,y2,… pairs.

Attributes

Use attributes to control which standard <area> fields appear in the Properties panel, and customAttributes to add any non-standard attributes:

js 
new kImgMap(img, {
  // show only href and alt
  attributes: ['href', 'alt'],

  // also expose custom data attributes
  customAttributes: ['data-value', 'data-category', 'data-popup'],
});

Custom attributes are written to the output HTML verbatim. They are also parsed back in when the textarea contains existing <area> tags.

Output

kImgMap writes output to the associated textarea on every change and when the modal is saved. Two formats are available:

Areas only (output: 'areas')

html
<area shape="rect" coords="60,50,280,200" href="/page" alt="Region">
<area shape="circle" coords="480,200,80" href="/hub" alt="Hub">

Full map wrapper (output: 'map')

html
<map name="my-map">
  <area shape="rect" coords="60,50,280,200" href="/page" alt="Region">
  <area shape="circle" coords="480,200,80" href="/hub" alt="Hub">
</map>

Callbacks

js 
new kImgMap(img, {
  // Fired on every change (draw, drag, resize, attribute edit)
  onUpdate(html, areas) {
    console.log('Updated:', areas.length, 'areas');
    myOutput.textContent = html;
  },

  // Fired only when the modal Save button is clicked
  onSave(html, areas) {
    fetch('/save-map', {
      method: 'POST',
      body: JSON.stringify({ html, areas }),
    });
  },

  // Lifecycle
  onOpen() { console.log('Editor opened'); },
  onClose(saved) { console.log('Editor closed, saved:', saved); },
});

Instance API

MethodReturnsDescription
open() void Open the modal editor (modal mode only). Re-parses the textarea first.
close(saved?) void Close the modal immediately (no confirmation). close() / close(false) discards changes made since it opened; close(true) keeps them. Safe to call from inside onSave.
getAreas() Area[] Return a deep copy of all current area objects.
setAreas(areas) void Replace all areas with the supplied array. Re-renders, syncs output and starts a new undo history. Each area needs a known shape and enough numeric coords (an array, or a string as in HTML); others are skipped with a console warning. Ids are made unique strings; attribute names that can't be written to a tag are dropped. Throws a TypeError if areas isn't an array.
undo() / redo() void Undo or redo the last change (also Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z / Ctrl+Y and the toolbar buttons). While a polygon is being drawn, undo() removes its last point. Each modal session (and each setAreas()) starts a new history of up to 100 steps.
getHTML() string Return the current output HTML string without syncing to the textarea.
destroy() void Remove all editor UI and restore the original DOM, including showing the textarea again. The image can then get a new editor.

Area object shape

js 
{
  id:     'kima-1-ab3c',     // internal unique id
  shape:  'rect',             // 'rect' | 'circle' | 'poly'
  coords: [60, 50, 280, 200], // natural-pixel coordinates
  attrs: {                    // attributes that are set (empty fields are absent)
    href:  '/page',
    alt:   'North Region',
    'data-value': 'north',
  },
}

Static API

MethodReturnsDescription
kImgMap.init(selector?, options?) kImgMap[] Initialise all matching containers. Default selector: '[data-kimgmap]'. Returns an array of instances; containers that already have an editor return the existing one.
kImgMap.get(img) kImgMap | null The editor attached to img (element or selector). An image has at most one editor — new kImgMap() on an image that already has one throws; destroy() it first.
kImgMap.responsive(img) function Scale the <map> that img's usemap points to so it lines up with the image at its displayed size, and keep it in sync on resize. img may be an element or selector. Returns stop(), which disconnects and restores the original coords. See Publishing the map.
kImgMap.version string The current plugin version string, e.g. '1.15.0'.

Dark Theme

kImgMap ships with built-in light and dark palettes.

1. The theme option

'dark' or 'light' fixes the palette; 'auto' follows the operating system's setting and switches live. It applies to the inline editor or to the modal from its first frame.

js 
new kImgMap(img, { theme: 'auto' });

Without the option you can set data-theme="dark" (or "light") on the .kimgmap-editor element of an inline editor yourself. The theme rules have no specificity, so your own token overrides still win inside them.

To override a component style rather than a token, match the plugin's selectors, which are scoped to the editor so CSS frameworks can't restyle it — e.g. .kimgmap-editor .kimgmap-tool { border-radius: 0; } (or .kimgmap-modal … for the modal's own buttons).

2. Via CSS custom properties

Override the surface and text variables on a parent element. This approach gives you full control:

css 
.my-dark-editor .kimgmap-editor {
  --kimgmap-bg:             #0f172a;
  --kimgmap-surface:        #1e293b;
  --kimgmap-surface-raised: #2d3d52;
  --kimgmap-border:         #334155;
  --kimgmap-text:           #f1f5f9;
  --kimgmap-text-muted:     #94a3b8;
}

3. Respect prefers-color-scheme

css 
@media (prefers-color-scheme: dark) {
  :root {
    --kimgmap-bg:             #0f172a;
    --kimgmap-surface:        #1e293b;
    --kimgmap-surface-raised: #2d3d52;
    --kimgmap-border:         #334155;
    --kimgmap-text:           #f1f5f9;
    --kimgmap-text-muted:     #94a3b8;
  }
}

Touch & Pen

All drawing and editing works with touch and pen input as well as a mouse (via Pointer Events). Dragging on the image draws or edits instead of scrolling the page — the overlay sets touch-action: none — so on small screens scroll using the area outside the image. Handles and hit targets are finger-sized while you use touch and shrink back when you use a mouse or pen (phones and tablets start large). Only the first finger is tracked; extra touches are ignored, and an interrupted touch (pointercancel) undoes the in-progress change.

With a pen, only tip contact draws or edits (barrel and eraser buttons are ignored), hovering shows the polygon preview line, and touches that land while the pen is drawing — e.g. a resting palm — are ignored.

Accessibility

kImgMap aims for WCAG 2.2 AA. The modal is a labelled dialog (the page behind it is made inert, focus is trapped and returned to the trigger on close); the toolbar is an ARIA toolbar with pressed states; the area list is a listbox; a polite live region announces additions, deletions, selection and polygon progress; validation errors mark fields aria-invalid and move focus to them. Default colours meet 4.5:1 text and 3:1 field-border contrast in both themes, selection is shown by stroke weight and a list marker rather than colour alone, and forced-colours and prefers-reduced-motion are supported. If you override the colour tokens, keep their contrast; for a custom dark palette, also use theme: 'dark' so the danger, error-text and field-border tokens are the dark-background versions.

Coordinate Format

All coordinates are stored in the standard HTML imagemap format — natural image pixels, measured from the top-left corner of the image at its natural (intrinsic) dimensions. The editor works at any display size, but note that browsers apply <area> coordinates to the image as rendered: the published map lines up when the image is shown at its natural size, and needs scaling when it is displayed larger or smaller — see Publishing the map.

For srcset images with w descriptors (a.jpg 800w, b.jpg 1600w), whose natural size depends on the viewport, the largest candidate's declared width (with the image's aspect ratio) defines the coordinate space.

Shapecoords format
rectx1,y1,x2,y2 — top-left and bottom-right corners
circlecx,cy,r — center and radius
polyx1,y1,x2,y2,… — flat list of vertex pairs
Note: While editing, kImgMap maps the pointer to natural pixels via SVG viewBox, so the editor works at any display size. On the published page, scale the coordinates if the image is displayed at a size different from its natural dimensions.

Publishing the Map

Connect the image to the map with usemap, using output: 'map' (or your own <map> wrapper):

html 
<img src="floorplan.jpg" usemap="#floorplan" alt="Floor plan">
<map name="floorplan">
  <area shape="rect" coords="60,50,280,200" href="/north" alt="North wing">
</map>

If the image is displayed at any size other than its natural size (e.g. max-width: 100% on a responsive page), scale the map to fit with kImgMap.responsive(). It only needs the JavaScript file. The map's coords must be in the image's natural pixels (what kImgMap writes); don't put padding or a border on the mapped image (browsers differ on where they measure from); the map is found by name or id; calling it again for the same image returns the same stop(), and one map can't serve two images shown at different sizes.

js 
const stop = kImgMap.responsive('img[usemap="#floorplan"]');  // keeps the map in sync on resize
// stop() disconnects and restores the original coords
Untrusted editors: kImgMap escapes attribute values and never writes an attribute name that could break out of the tag, but it keeps whatever attributes the input has — including event handlers such as onclick and javascript: URLs. If people you don't trust can edit maps, sanitise the saved HTML on the server.

An image can have only one editor: a second new kImgMap() throws and kImgMap.init() returns the existing one. New kImgMap.get(img). open() after destroy() does nothing.

  • Breaking: callbacks (onUpdate, onSave, onAttributeChange) now receive copies of the areas, so changing them no longer changes the editor — use setAreas().
  • Fixed: a page that stopped pointerup from bubbling could leave a drag stuck; the listeners are now capture-phase on window.
  • Fixed: CSS frameworks such as Pico restyled the editor's buttons, fields and labels, and the Edit Image Map / Show Code buttons. The plugin now uses border-box sizing throughout and resets its controls with selectors that outrank framework rules.
